# 七夕活动完整内容与生成来源审计

> 审计对象：`codex/qixi-smart-context` 当前版本的七夕活动。
> 目的：从策划视角完整说明用户逐屏看见什么、做什么、得到什么；每段内容究竟是代码写死、模板插值，还是 LLM 生成。

## 0. 先把结构说准

这不是“8 条独立剧情线”。实际结构是：

```text
特别时光活动卡
  ↓ 选择角色
七夕活动首页
  ↓ 进入梦境
假 ChatApp
  ↓ 点击输入框
聊天碎裂与白兔门
  ↓ 跟上白兔
夹层入口
  ↓ 三选一（只影响后面一句旁白，不分剧情线）
由 8 个地点组成的互通地图
  ↓ 在至少 5 个地点互动，并完成 3 个指定地点
隐藏内层（4 页线性独白）
  ↓
按住屏幕 1.25 秒
  ↓ 松手
七夕结局
```

8 个地点是同一张地图上的节点：

```text
                         七姐人格寄存处
                        ↗              ↘
没有上一句的空地 → 供果冷藏走廊       乞巧市·小票雨
       │                                   ↕
       ├→ 七孔括号巷 ──────────────────────┘
       │
       └→ 投针验巧光井 ↔ 葡萄架下的未发送站台 ↔ 双星逆向光标井
                                  ↑
                            小票雨也可到达
```

隐藏内层不算第 9 个自由探索地点，它是满足条件后出现的一条线性结局路径。

## 1. 内容来源图例

- **【写死】**：代码里直接写好的固定文本，所有角色和用户看到的内容相同。
- **【模板】**：整句话写死，只把 `${char.name}` 或 `${user.name}` 替换成当前角色名、用户名。
- **【LLM】**：活动首次开始时由模型生成并缓存；不同角色、聊天和记忆可能不同。
- **【状态】**：根据探索数量、是否有存档、是否按住足够久等状态，从几句写死文本中选择一句。
- **【不可达】**：组件代码存在，但当前界面没有入口，正常用户到不了。

## 2. 一眼看懂：LLM 实际只负责哪些内容

LLM **不会**生成整场活动，也不会实时扮演角色推进剧情。

它只生成一次“记忆素材包”：

1. 2–5 个记忆锚点：
   - `anchor.object`：记忆里的真实物件、词或动作。
   - `anchor.fact`：一条具体、可核对的共同记忆事实。
2. 7 个地点各自的一份记忆映射 `beat`：
   - `memoryLine`：记忆在这个梦境地点怎样出现。
   - `ritualAction`：给用户新增的一个动作按钮。
   - `result`：点击这个 LLM 动作后的结果。
   - `extension`：地点互动结果下面追加的一句延伸。
3. `finalEcho`：最终黑屏牵手页面最前面的一句短角色回声。

除以上字段外，下面这些全部写死：

- 活动标题、简介和假 ChatApp 台词。
- 白兔、坠落、入口三选一。
- 8 个地点的名字、场景说明、NPC、地图和路线。
- 每个地点原有的 2–3 个动作及动作结果。
- “角色也在找用户”的整个核心主题。
- 隐藏内层 4 页角色独白。
- 隔屏牵手的 5 段长台词。
- 七夕结局台词。
- 月相、任务、商店等外围模块。

## 4. 八地点地图的统一玩法

每个地点都按同一套循环运行：

```text
进入地点
  ↓
显示写死的地点标题、首次/再次访问说明、NPC 文案
  ↓
如果该地点有有效 LLM beat：显示记忆证据和一个 LLM 动作
  ↓
用户从动作中选择一个
  ↓
显示对应结果
  ↓
如果该地点有 LLM beat：无论选了哪个动作，都追加 beat.extension
  ↓
用户必须再点一次“离开”
  ↓
星图出现，用户只能去当前地点的相邻节点
```

### 4.1 有 LLM 与无 LLM 时，按钮数量不一样

- 没有有效 LLM beat：显示该地点全部 2–3 个写死动作。
- 有有效 LLM beat：显示 `1 个 LLM 动作 + 原写死动作的前 2 个`。
- 因此，原本有 3 个写死动作的地点，在 LLM 成功后，第 3 个写死动作会被隐藏。
- 起点 `origin` 从不生成 LLM beat，所以永远只有 2 个写死动作。

### 4.2 地图阶段文案

按“已经互动的不同地点数”切换：

- 0 处：`初更 · 观星 · 先辨认两颗各自发亮的星`
- 1–2 处：`二更 · 听河 · 安静下来，听见另一侧的动静`
- 3–4 处：`夜半 · 乞巧 · 把细小的痕迹一段段穿起来`
- 5 处及以上：`将明 · 架桥 · 两条相反的轨迹正在靠近`

### 4.3 全局“另一边也在找你”提示

- 完成 1 处后【写死】：

  > 远处那颗缺角的星闪了一下。不是回应，更像有人也碰到了线。

- 完成 2–3 处后【写死】：

  > 一枚很淡的红色光标从远处经过，方向与你相反。你第一次确定：另一边也在移动。

- 完成 4–5 处后【模板】：

  > 这里刚有人经过。ta 留下的问题总是同一个：“【用户名】来过吗？”

- 完成 6 处及以上【写死】：

  > 你留下的细线不再散落。它们被另一端逐段接起，正往同一个方向绷紧。

### 4.4 星图目标提示

- 未完成 5 处：【状态模板】`再去 N 个未点亮地点，收集能搭桥的痕迹`
- 已完成 5 处但缺指定地点：【写死】`投针井、葡萄架与逆向光标各藏着一段互相寻找的证据`
- 已解锁但不在终点：【写死】`桥已经接通：沿亮起的路线去双星逆向光标井`
- 已解锁且在终点：【写死】`桥已经接通：进入那条不该存在的内层`

### 4.5 隐藏内层的真实触发条件

必须同时满足：

1. 已在至少 5 个不同地点选择过动作。
2. 在“投针验巧光井”选择过任意动作，得到 `search-well`。
3. 在“葡萄架下的未发送站台”选择过任意动作，得到 `search-platform`。
4. 在“双星逆向光标井”选择过任意动作，得到 `reverse-caret`。
5. 当前重新位于“双星逆向光标井”。
6. 互动后再点“离开”，让星图显示出来。

这时星图下面才出现：

- 【写死】标题：`一条不该存在的内层`
- 【写死】按钮说明：`跟上光标 →`

所谓“痕迹”并不取决于用户选了哪个具体选项；同一地点所有选项都会给相同的节点痕迹。

## 5. 八个地点逐一拆解

### 5.1 地点 01：没有上一句的空地（`origin`）

来源结论：**100% 写死，无任何 LLM 内容。**

相邻地点：

- 供果冷藏走廊
- 七孔括号巷
- 投针验巧光井

固定场景：

- 【写死】名称：`没有上一句的空地`
- 【写死】眉题：`初更 · 双星尚未命名`
- 【写死】首次进入说明：

  > 七月初七的夜色漏进夹层。四周像一段对话刚被全部选中，又忘了按删除。

- 【写死】再次进入说明：

  > 你回到空地。两颗星仍各自悬着，其中一颗的位置比刚才近了一点。

- 【写死】“遇见”：

  > 这里没有人。地上只有你的名字，少了最后一个字；很远的地方，另一颗星也缺了一角。

选项 1：

- 【写死按钮】`捡起自己名字旁边那一小截星线`
- 【模板结果】：

  > 星线很轻，另一端却绷着。标签背面写着：“如果见到【用户名】，让 ta 原地等一下。”落款被撕走了。

选项 2：

- 【写死按钮】`把标签朝远处那颗缺角的星推过去`
- 【写死结果】：

  > 标签没有飘远，星线却被另一端接住了一瞬。那里确实有谁，只是你们之间还没有路。

节点痕迹：`half-name`。

### 5.2 地点 02：供果冷藏走廊（`coldCorridor`）

来源结论：**场景和原有选项写死；可以插入 1 组 LLM 记忆内容。**

相邻地点：

- 没有上一句的空地
- 七姐人格寄存处

固定场景：

- 【写死】名称：`供果冷藏走廊`
- 【写死】眉题：`乞巧供桌 · 温度仍然有效`
- 【写死】首次进入说明：

  > 传统供品努力维持庄重，旁边那盒明天到期的草莓牛奶显然没有配合。

- 【写死】再次进入说明：

  > 你再次拉开柜门。少了一盒牛奶；湿脚印却一路朝与你相反的方向跑了。

- 【写死】“遇见”：

  > 巧果、草莓牛奶和猫爪吸管套摆成供品。冷柜里还并排睡着三种 Sully，没有一种肯承认自己是本人。

硬编码问题：这里的 `Sully` 是字面量，不会随用户选择的角色改变。

该地点的 LLM 生成要求：

> 从真实聊天或记忆中找到一件确实出现过的小东西、食物、礼物或交换行为，把它放上供桌；不得凭空发明礼物。

有有效 LLM beat 时，会在固定场景下面显示：

- 【LLM】`anchor.object`
- 【LLM】`anchor.fact`
- 【LLM】`beat.memoryLine`
- 【LLM 按钮】`beat.ritualAction`
- 【LLM 按钮结果】`beat.result`
- 【LLM 追加句】`beat.extension`

固定选项 1：

- 【写死按钮】`敲敲“甜言蜜语味”的盒子`
- 【写死结果】：

  > 盒子立刻说：“我永远不会让你等。”冷柜在“永远”两个字上结了一层假霜。

固定选项 2：

- 【写死按钮】`摇醒“只会打盹味”的盒子`
- 【模板结果】：

  > 它打着哈欠说：“【角色名】不在。本人刚拿走原味那盒，问你是不是往括号那边去了。”

固定选项 3：

- 【写死按钮】`把一枚巧果掰成两半，留一半在原味盒旁`
- 【写死结果】：

  > 巧果不算好吃，胜在确实由你完成。水珠下面多了一枚刚按上去的指印；另一半已经被谁拿走。

显示规则：有 LLM beat 时，固定选项 3 被隐藏；无 LLM beat 时显示全部 3 个固定选项。

节点痕迹：`milk-memory`。

### 5.3 地点 03：七孔括号巷（`bracketCorner`）

来源结论：**场景和 2 个原有选项写死；可以插入 1 组 LLM 记忆内容。**

相邻地点：

- 没有上一句的空地
- 乞巧市·小票雨

固定场景：

- 【写死】名称：`七孔括号巷`
- 【写死】眉题：`穿针乞巧 · 请站在句内`
- 【写死】首次进入说明：

  > 左括号说自己只负责开始，右括号说结束从来不是它决定的。负责穿线的逗号已经累趴了。

- 【写死】再次进入说明：

  > 它们认出你，七对括号一起给中间让出一个人的宽度；红线另一端似乎被谁轻轻拉了一下。

- 【写死】“遇见”：

  > 七对空括号排成针孔。一根红色光标线试了六次，每次都在最后一个括号前打结。

该地点的 LLM 生成要求：

> 使用一次“因为想与对方分享、抵达对方，而耐心学会、改好或做成某件事”的真实记忆。Prompt 强制要求保留“不是祈求被爱，而是爱让人愿意变得更有能力去创造”的主题。

有有效 LLM beat 时插入相同的 6 个字段：`anchor.object`、`anchor.fact`、`memoryLine`、`ritualAction`、`result`、`extension`。

固定选项 1：

- 【写死按钮】`耐心把红色光标线穿过七个括号`
- 【模板结果】：

  > 前六个都很顺。最后一个孔抖得厉害，像被另一端拉住。线穿过去时，巷口传来一句：“【用户名】刚才是不是在这里？”

固定选项 2：

- 【写死按钮】`请累趴的逗号帮你扶住最后一个针孔`
- 【写死结果】：

  > 逗号骂骂咧咧地站起来。你们一起把线穿过去；它没有变成奖章，只是在地图上多连亮了一小段。

显示规则：有 LLM beat 时显示 `1 个 LLM 选项 + 上述 2 个固定选项`；无 LLM beat 时只显示上述 2 个固定选项。

节点痕迹：`bracket-witness`。

## 9. LLM 生成机制完整说明

### 9.1 什么时候调用

用户点击“进入梦境”时：

1. 先用角色 ID 查本地 `qixi memory bundle` 缓存。
2. 命中缓存：直接复用，不调用 LLM。
3. 没缓存且 API 完整：调用一次主模型。
4. 没有 API：使用空素材包，整场靠写死文本继续。
5. “继续上次探索”不会为了旧存档补调一次模型。

### 9.2 给 LLM 的输入

#### A. 记忆宫殿召回

固定召回查询：

```text
七夕 共同创造 想分享 冷战 苦恼 撤回 沉默 小礼物 想起对方 一起完成的事
```

召回结果被注入角色副本的上下文。

#### B. 最近聊天

- 读取当前角色最近 60 条消息。
- 文本拼接后只保留最后约 9000 字符。
- 图片消息只转成 `[图片]`，图片内容本身不会给模型。

#### C. 角色与用户资料

通过核心上下文构建器加入角色设定、用户资料及已召回记忆。

### 9.3 Prompt 对模型的硬性要求

模型被要求：

1. 只使用上下文明确出现的事实。
2. 不得补造日期、原话、礼物、动作、争吵、承诺或关系身份。
3. 没有准确原话时只能转述，不能伪造引号。
4. 没有某类记忆时，可以让多个地点复用同一真实锚点。
5. `anchor.fact` 必须是具体事件，不能写“你们共同经历了很多”。
6. `anchor.object` 只能是记忆里真实出现过的词、物件或动作。
7. `ritualAction` 必须是玩家能在场景中执行的动作。
8. `result` 必须是该记忆在梦境中的视觉反馈。
9. `extension` 只能从记忆自然引申一小步，不能说教或替用户下爱情结论。
10. 括号巷必须表达“因为想抵达对方而学习、创造、做得更好”。
11. 光标井只能连接已有痕迹，不得新增宏大誓言。
12. `finalEcho` 必须很短，不得承诺永远。

    {
      "id": "m1",
      "fact": "真实记忆的一句话",

  "beats": {
    "coldCorridor": {
      "anchorId": "m1",
      "memoryLine": "记忆如何在供果走廊出现",

      "result": "动作后的梦境反馈",
      "extension": "由这段记忆自然长出的一句延伸"
    },
    "bracketCorner": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." },
    "lightWell": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." },
    "maskCounter": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." },
    "receiptRain": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." },
    "unsentPlatform": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." },
    "typingShaft": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." }

### 9.5 校验与整包降级

模型输出必须同时满足：

- 至少 2 个有效 `anchors`。
- 至少 4 个有效 `beats`。
- 每个 beat 的 `anchorId` 必须指向存在的 anchor。
- `memoryLine`、`ritualAction`、`result`、`extension` 都必须达到最低长度。

任何一个整包条件失败，不会只丢掉坏节点，而是整个素材包降级为空：

```json
{
  "source": "fallback",
  "anchors": [],
  "beats": {},
  "finalEcho": ""
}
```

此时用户看到的就是全部写死版本。

### 9.6 LLM 字段在画面里的精确位置

每个有 beat 的地点，在固定 NPC 文案下面出现：

```text
这处梦境认出了                   ← 写死标签
【anchor.object】                 ← LLM
【anchor.fact】                   ← LLM
【beat.memoryLine】               ← LLM
```

动作区：

```text
【beat.ritualAction】             ← LLM 生成的第一个按钮
【固定按钮 1】                    ← 写死
【固定按钮 2】                    ← 写死或模板
```

点击 LLM 按钮：

```text
你在这里做过一件事               ← 写死标签
【beat.result】                   ← LLM
【beat.extension】                ← LLM
```

点击固定按钮：

```text
你在这里做过一件事               ← 写死标签
【固定结果】                      ← 写死或模板
【beat.extension】                ← 只要该地点有 beat，仍然追加 LLM 句
```

因此 `extension` 并不只属于 LLM 按钮；即使用户选了写死动作，它也会显示。

## 12. 当前内容结构的策划事实

1. 玩家不是在走 8 条故事线，而是在同一张图上访问 8 个场景。
2. 入口三选一不是剧情分支，只替换一句旁白。
3. 8 个地点里，只有 7 个可以加入 LLM 个性化内容；起点完全写死。
4. 每个可生成地点最多只增加 1 个 LLM 动作，不会让角色自由对话。
5. LLM 成功时会隐藏部分原有第 3 选项。
6. 用户选固定动作后，仍会看到该地点 LLM 生成的 `extension`。
7. 隐藏结局要求至少 5 地点，并强制包含光井、未发送站台、光标井。
8. “人格外壳”“角色也在找你”“AI 已进入用户生活”等最核心表达全部写死，不来自用户真实记忆。
9. 冷藏走廊把 `Sully` 写死，人格寄存处把 `User` 写死，换角色或用户名时会穿帮。
10. 章节、月相、任务、收藏已经写了完整内容，但目前用户进不去。
